# shuttle-planner

放課後等デイサービスや通所介護の送迎を、施設の端末だけで組むための送迎計画アプリです。誰がどの車に乗るか、どの順で迎えに行き何時に着くかまでをその場で出し、ドライバーは各利用者の横から地図アプリの案内を始められます。

デモ: https://cannotfly1020-hub.github.io/shuttle-planner/

## 概要

配車担当が朝にやっている作業を、ひとつの画面にまとめています。

- その日に出す車両と、乗車する利用者を選ぶ
- 定員・専用車両・車椅子・添乗の条件を満たす割り当てを出す
- 施設を出て自宅を回り、施設に戻る順序と到着時刻を出す
- ドライバーが「地図」をタップすると、その地点への車の案内が開く

距離と所要時間は端末の中で計算します。有料の地図APIは使っていません。緯度・経度の直線距離に、市街地の回り道として 1.35 倍を掛け、時速 20km で分に換算します。座標が無い区間は、登録順のまま 5 分として積算し、画面は止まりません。

## 機能

- **曜日と当日の変更。** 利用曜日、車両の稼働日、欠席、当日スポット、その日だけの運休を反映してから配車します。
- **車両と人の条件。** 定員、専用車両への拘束、車椅子など必要な装備、添乗員、役割マスタを施設ごとに持てます。
- **巡回と到着予測。** 施設を出発地・到着地に固定し、2-opt で短い回り方を選びます。乗降は一律ではなく、一般 2 分、見守り・単独乗車NG は 5 分、車椅子は 8 分です。個別の分数があればそちらを優先します。
- **ワンタップ案内。** タイムラインの各利用者に「地図」があります。座標があればそのピン、無ければ住所を目的地にした Google マップの経路案内（`travelmode=driving`）を開きます。APIキーは不要です。案内アプリを開くときだけ通信します。
- **共有用テキスト。** 割り当てと巡回時刻を、LINE やチャットに貼れる文面でコピーできます。
- **端末内に保存。** 利用者、車両、施設、マスタはブラウザの localStorage に残ります。

## 導入すると変わること

- 地図APIの月額を足さずに、順番と到着時刻を出せます。
- 担当者が手で並べていた「誰の次に誰を迎えるか」が、運行計画の生成後に分単位で並びます。
- ドライバーはチャットの住所を地図アプリへ打ち直さず、その人の「地図」から案内を始められます。
- 電波が不安定な送迎中でも、配車と時刻の計算自体は端末だけで済みます。
- 事務所では、コピーした運行計画をそのまま申し送りに使えます。

## 使い方

1. 上のデモ、または `www/index.html` を開く。
2. 利用者に住所を入れる。ピンを固定したいときは緯度・経度も入れる。
3. 出発時刻を確認し、「運行計画を生成」を押す。
4. 各車両の巡回で、利用者の右にある「地図」をタップする。

座標も住所も無い利用者には地図ボタンは出ません。住所か座標を登録すると、次の生成から出ます。

## 構成

アプリ本体は `www/` です。Capacitor の `webDir` もここを見ています。GitHub Pages は `main` への push で `www/` だけを公開します。リポジトリ直下の `index.html` は公開サイトには含まれません。

ローカルで確認するときは、`www` で静的サーバを起動します。

```bash
cd www && python3 -m http.server 8787
```
